# Dallal — Canonical Operational Data Model

*Implementation: [`backend/dallal/data/schema.py`](../../backend/dallal/data/schema.py) (pydantic models, enums, `validate_frame`) · Adapters: [`backend/dallal/data/adapters/`](../../backend/dallal/data/adapters/)*

## Principle

Public datasets come from different domains and are **never concatenated**. Each adapter maps its source into the subset of these tables it can legitimately provide and **declares that subset** (`PROVIDES`). Anything outside it stays null — never imputed with plausible values. `validate_frame` rejects a table that fills an undeclared column, so a silent over-claim fails the build.

## Provenance on every row of every table

| `origin` | Meaning | Allowed in held-out evaluation? |
|---|---|---|
| `observed` | recorded by a real operational system, published by the source | yes |
| `engineered` | label/feature derived from observed data (definition versioned) | yes (labels only) |
| `synthetic` | generated by us (augmentation) or by a third-party simulation (OCEL) — requires `scenario_id` | **never** (splitter raises) |
| `demo` | the frontend's deterministic demo world | **never** |

Plus `source_id` (registry id), `source_record_id`, `adapter_version`, `scenario_id`, `generator_seed`. `shipment_id` is always `"<source>:<native id>"`, so ids never collide across sources.

## Tables

| Table | Key | What it holds |
|---|---|---|
| `node` | node_id | hubs, branches, pickup points, lockers, sellers (kind, city, lat/lng, capacity) |
| `courier` | courier_id | couriers/drivers |
| `route`, `stop` | route_id, stop_id | planned/actual sequence, zone, windows (timestamp *or* offset), planned service time |
| `shipment` | shipment_id | service, promised window, destination, payment/COD, value, volume, `attrs` |
| `event` | event_id | typed events (created … delivered, GPS ping, contact) with `ts` + `ts_quality` (exact · yearless · offset · day_only · unknown) + raw source code |
| `attempt` | attempt_id | one row per delivery visit: outcome, attempt_no, stop, **`failure_reason` (null unless the source states it)** |
| `address_context`, `recipient_context` | shipment_id | address confidence/history; recipient responsiveness, confirmed window, missed windows |
| `node_state`, `corridor_state` | state id | backlog, last scan, online/offline; corridor speed vs typical, exception baseline |
| `exception` | exception_id | recorded exception code (the human-entered record that Dallal cross-checks) |
| `incident`, `incident_member` | incident_id | systemic incidents and their affected/exposed shipments (root cause known only for injected ones) |
| `action`, `decision`, `outcome` | ids | the learning ledger: assignment mechanism, logged propensity, policy id, frozen context snapshot, outcome (initially `pending`) |
| `label` | label_id | engineered supervision, **separate from facts**, with `as_of` and `available_at` |

## Leakage rules built into the model

1. **Labels are their own table** with `as_of` (prediction instant) and `available_at` (when the outcome becomes knowable); `available_at > as_of` is validated.
2. **Feature builders may use only `ts ≤ as_of`**; untimed events are visible only on strictly earlier days (`visible_events`).
3. **History features** use only outcomes already resolved before `as_of` (`past_stat`) with a train-only prior.
4. **Post-hoc source fields are quarantined**: Amazon `route_score` is stored as `plan_quality` and banned from pre-dispatch features; actual stop order is banned for pre-dispatch tasks.
5. **Name-independent guard**: a feature that alone gives AUC ≥ 0.98 aborts training.
6. **Time-aware splits with embargo**; synthetic/demo rows rejected from valid/test.
7. **Inference-time**: `Bundle` accessors filter to `as_of`, so the agent cannot see the future either.

## Known source limitations preserved on purpose

LaDe timestamps have no year (`yearless`; ordering valid within the 6-month span) · Amazon visits are untimed and reasonless, 3,072 evaluation routes have no outcomes and are not used · route-deviation has 3,049 sentinel-scale time rows whose offsets are nulled (counted, not hidden) · Olist 1.4% of hand-off stamps precede payment approval (kept).
